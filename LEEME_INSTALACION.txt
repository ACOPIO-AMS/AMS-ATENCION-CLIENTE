  crecen con cantidad registrada); respeta los diseños A4 existentes.

  tipográfico en impresión.

INSTALACIÓN RECOMENDADA EN ESTE ORDEN
1. Respaldar el index.html, ams-cloud.js y config.js actuales de GitHub.
2. Supabase -> SQL Editor: ejecutar 01_RENOMBRAR_USUARIO.sql una vez.
   Verificar usuario y contraseña conservada en el SELECT final.
3. Supabase -> Edge Functions: crear 'ams-consultas', pegar todo
   ams-consultas-index.ts y publicar. Verify JWT with legacy secret OFF.
   Requiere secretos predeterminados SUPABASE_URL / SUPABASE_SERVICE_ROLE_KEY
   y el existente AMS_ALLOWED_ORIGINS=https://acopio-ams.github.io.
   NO usar la clave de importación de catálogos en el frontend.
4. ANTES de reemplazar la web, probar consulta con token de administrador
   desde la consola de Supabase, sin mostrar token ni PIN públicamente:
   POST {"tipo":"dni","valor":"DNI_EXISTENTE"} con Header
   Authorization: Bearer <TOKEN_DE_SESION_ADMIN>.
   Verificar ok:true y datos correctos. Repetir tipo:ruc con 11 dígitos.
5. En GitHub ACOPIO-AMS/AMS-ATENCION-CLIENTE, reemplazar SOLO
   index.html, ams-cloud.js y config.js en un mismo commit.
6. Esperar despliegue GitHub Pages, refrescar Ctrl+F5.
   Probar como admin (solo PIN) y un operario (usuario+clave).
   Probar DNI, historial con varias personas, cargos y reportes.
7. Separadamente, cuando autorices respaldo a BD SALIDAS, instalar
   02_RESPALDO_BD_SALIDAS.gs en proyecto Apps Script independiente
   con acceso al libro MATRIZ PROVEEDORES; configurar propiedades:
   AMS2_API_URL: https://oxadhudyjkviidnwyzpf.supabase.co/functions/v1/ams-api-v7
   AMS2_BACKUP_TOKEN: la misma clave privada que AMS_BACKUP_TOKEN en Supabase.
   Ejecutar primero AMS2_probarConexion; después AMS2_actualizar MANUAL;
   comprobar que NO se han modificado estados RECEPTADOS/RECIBIDOS.
   Solo después ejecutar AMS2_instalar (activador cada 10 min).
   Este archivo ya abre MATRIZ PROVEEDORES por el ID conocido del libro.
   Verifica que ese ID siga siendo el mismo y que Apps Script tenga acceso.
